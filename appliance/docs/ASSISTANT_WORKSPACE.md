# Assistant workspace

The workspace brings the current call flow, approved answers, conversation tests,
call review, and voice settings into one connected navigation. Its reference is
the owner's open OutreachGenius Voice script window, inspected in Avast using
its Script and Test views. No OutreachGenius assets, customer records, or private
campaign prompt are included in the source.

| View | Purpose |
| --- | --- |
| `/assistant` | Read the actual greeting, call flow, configured model, selected voice, pace, and approved document count. |
| `/knowledge` | Maintain business answers using the existing draft/approved controls. |
| `/simulator` | Start a text conversation, try a caller scenario, inspect captured details, and open the saved transcript. |
| `/call-review` | Review observations linked to saved call evidence. |
| `/voice` | Administrators can preview and save the installed voice and pace. |

The call-flow page is read-only. It does not introduce a free-form routing prompt
or a script publishing system. Knowledge approval and voice saves retain their
existing behavior. There is no automatic model training from call feedback.

Calls also have quick views for reported problems, delivery failures, and emergency
priority. Counts come from the displayed recent records. Search and filter choices
survive a reload through the page URL. They do not claim to search older records.

## Test isolation

The text simulator uses a separate `VoiceCore` instance with the same settings,
business directory, approved knowledge, language model, and intake implementation.
It has a notification sink and no Business Suite bridge or automatic briefing
queue. Emergency and completion tests therefore save local records without sending
staff alerts, syncing remote work, or placing a phone call.

New test identifiers are generated by the server. An unknown identifier cannot be
used to reset or delete a real call. Starting another test closes the previous
session and retains its transcript. Ended tests leave the in-memory session map.
Manager access and CSRF validation remain required. Simulations remain excluded
from the existing real-call quality report.

Text tests exercise wording, intake, and routing decisions. They do not exercise
speech recognition, synthesis, interruption handling, carrier transfers, or audio
latency. The local streaming voice trial remains a separate deployment choice.

## Design decisions

Reading this as an operations workspace for Floodman staff, using the owner's
OutreachGenius organization reference and the established Floodman navy and blue
interface: ENERGY 1 / RHYTHM 2 / MOTION 1.

- Navy preserves the existing Floodman navigation hierarchy; blue identifies actions and the current workspace view.
- Adjacent workspace links reduce the distance between reading the flow, testing it, and reviewing evidence.
- The first message is the focal point because missing introductions were a reported call problem.
- The test conversation and captured details sit together so staff can inspect what the assistant understood.
- System typography keeps long requests readable without downloading fonts.
- Borders separate records and working areas; panels do not need decorative elevation.
- Narrow screens stack the work areas; intermediate screens arrange supporting test panels in two columns.
- Status text describes actual state. The former unconditional “Local model ready” label is removed from the simulator.
- Existing branded marks are retained. No new logos, portraits, illustrations, or animations are introduced.

## Verification

The complete suite passed with **462 tests passed and one skipped**. The skipped
test requires FFmpeg, which is supplied by the CPU image and was unavailable in
the Windows test environment. The workspace/portal tests were also run after the
final presentation changes.

Browser verification uses synthetic records and a temporary loopback-only runtime
under `DATA_DIR`. It starts and stops its own server. Screenshots and detailed
click-through evidence remain in `data/outreach-review/private/`, outside source.
The checks cover all added workspace destinations and controls, every quick view
and filter option, search persistence, both clear buttons, all four scenarios,
retained transcripts, loading, failure, restart, mobile navigation, and keyboard
activation. Six connected views were checked at 320, 390, 650, 768, 1024, 1180,
and 1440 pixels. The two new views also passed 200% text enlargement at 390 pixels.
